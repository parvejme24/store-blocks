# Contracts

Contracts are the interfaces that let StoreBlocks swap databases, storage providers, and payment gateways without touching the rest of the code. Types live in `packages/module-kit/src/contracts/` and are copied into generated projects. **Changing a contract requires an ADR and a major version bump.**

## General Rules

- IDs are `string` everywhere outside repositories.
- Repositories and adapters return **shared types** from `shared/`, never ORM documents, rows, or SDK responses.
- Money is stored as **integer minor units** (poisha / cents) plus a currency code. Never floating point.
- Dates are `Date` objects in TypeScript and ISO 8601 strings over HTTP.
- Expected failures (not found, conflict) are expressed as return values (`null`, `false`) or typed `AppError`s, never raw driver errors.

## Repository

Each module defines its own repository interface. A typical shape:

```ts
export interface ProductRepository {
  findMany(query: ProductQuery): Promise<Paginated<Product>>;
  findById(id: string, tx?: TxContext): Promise<Product | null>;
  findBySlug(slug: string): Promise<Product | null>;
  create(input: CreateProductInput, tx?: TxContext): Promise<Product>;
  update(id: string, input: UpdateProductInput, tx?: TxContext): Promise<Product | null>;
  delete(id: string, tx?: TxContext): Promise<boolean>;
  decrementStock(id: string, qty: number, tx: TxContext): Promise<boolean>;
}

export interface Paginated<T> {
  items: T[];
  page: number;
  limit: number;
  total: number;
  totalPages: number;
}
```

Rules:

- `findById` / `findBySlug` return `null` when not found.
- `update` returns `null` when the record does not exist.
- `delete` returns `false` when nothing was deleted.
- Methods used inside transactions accept an optional (or required) `tx`.
- `decrementStock` must be atomic and return `false` if stock would go negative.
- Implementations live in `db/mongodb/` and `db/postgresql/` and must both pass the module's contract suite.

## UnitOfWork

```ts
export type TxContext = unknown; // ClientSession (MongoDB) or Drizzle transaction (PostgreSQL)

export interface UnitOfWork {
  run<T>(fn: (tx: TxContext) => Promise<T>): Promise<T>;
}
```

- MongoDB: wraps `session.withTransaction()`. Requires a replica set (MongoDB Atlas provides one; the local Docker config enables one).
- PostgreSQL: wraps `db.transaction()`.
- If `fn` throws, everything rolls back and the error is rethrown.
- Services use it for multi-step writes such as checkout.

## StorageAdapter

```ts
export interface StorageAdapter {
  readonly provider: "cloudinary" | "s3" | "local";

  getUploadUrl(input: {
    folder: string;
    contentType: string;
    sizeBytes: number;
  }): Promise<SignedUpload>;

  delete(key: string): Promise<void>;

  getPublicUrl(key: string, opts?: { width?: number; height?: number; format?: "webp" | "avif" }): string;
}

export interface SignedUpload {
  key: string;
  method: "PUT" | "POST";
  url: string;
  fields?: Record<string, string>;  // form fields for POST uploads (Cloudinary)
  headers?: Record<string, string>; // headers for PUT uploads (S3)
  expiresAt: Date;
}

export interface StoredFile {
  key: string;
  provider: StorageAdapter["provider"];
  alt?: string;
}
```

Rules:

- The storage core checks admin role, content type, and size **before** calling `getUploadUrl`.
- Signed URLs expire within 10 minutes.
- Keys are generated by the server (`<folder>/<yyyy>/<uuid>.<ext>`), never by the client.
- `delete` is idempotent: deleting a missing key does not throw.
- `getPublicUrl` is synchronous and must not call the network.
- The database stores `StoredFile`, never a full URL.

## PaymentAdapter

```ts
export interface PaymentAdapter {
  readonly id: "cod" | "sslcommerz" | "stripe" | string;
  readonly label: string;

  initiate(order: OrderForPayment): Promise<PaymentInitiation>;
  verify(req: PaymentCallbackRequest): Promise<PaymentVerification>;
  handleWebhook(req: PaymentWebhookRequest): Promise<PaymentVerification | null>;
}

export type PaymentInitiation =
  | { kind: "redirect"; url: string; transactionId: string }
  | { kind: "pending"; transactionId: string }; // e.g. Cash on Delivery

export interface PaymentVerification {
  transactionId: string;
  orderId: string;
  status: "paid" | "failed" | "cancelled" | "pending";
  amountMinor: number;
  currency: string;
  raw: unknown; // stored for audit; never logged in full
}
```

Rules:

- The payment core compares `amountMinor` and `currency` with the order before marking it paid.
- `handleWebhook` verifies signatures where the gateway supports them and returns `null` for events it ignores.
- Webhook processing is idempotent: the same `transactionId` never confirms an order twice.
- Adapters never change order status themselves; they report, and the orders service decides.
- Every adapter supports a sandbox mode controlled by env.

## Contract Test Suites

`module-kit` exports reusable suites:

```ts
runRepositoryContract("products", () => createProductRepository());
runStorageContract(() => createS3Adapter(testConfig));
runPaymentContract(() => createSslcommerzAdapter(sandboxConfig));
```

Every implementation must pass its suite in CI.
