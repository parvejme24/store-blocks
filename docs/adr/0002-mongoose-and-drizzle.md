# ADR 0002: Mongoose for MongoDB, Drizzle for PostgreSQL

- **Status:** Accepted
- **Date:** 2026-10-18

## Context

Users choose MongoDB or PostgreSQL when generating a store. The rest of the application must be identical for both. A single ORM covering both databases would mean one repository implementation per module instead of two.

## Decision

- **MongoDB:** Mongoose.
- **PostgreSQL:** Drizzle ORM with `drizzle-kit` for migrations.
- Each data module defines a repository interface with one implementation per database. Services, controllers, routes, and the frontend never know which database is in use.

## Alternatives Considered

| Option | Why not |
|---|---|
| Prisma for both databases | Prisma ORM v7 does not yet support MongoDB; the recommended version for MongoDB is v6. Using Prisma for both would pin every project, including PostgreSQL ones, to v6 and force a later v6 → v7 migration in every generated store. It also conflicts with our policy of installing current packages. |
| Prisma for PostgreSQL only | Viable, but a single `schema.prisma` is harder to assemble from per-module pieces than Drizzle's per-file TypeScript schemas, and Prisma adds a generation step. May be revisited after 1.0 as an optional third implementation. |
| Mongoose only (no SQL) | Many stores and hosts prefer PostgreSQL; relational integrity suits orders and payments. |
| A custom database abstraction | Re-inventing an ORM; worse than two mature, well-documented tools. |

Even with Prisma, the two databases would need separate schemas (ObjectId vs uuid), different migration flows, and a replica set for MongoDB, so the code would still diverge.

## Consequences

- Every data module ships two repository implementations and both must pass the same contract tests in CI.
- `UnitOfWork` abstracts transactions (`session.withTransaction()` vs `db.transaction()`).
- IDs are strings outside repositories; relational vs embedded modeling is hidden behind repositories.
- Drizzle is pre-1.0, so its packages use tilde ranges pinned to a tested minor.
- PostgreSQL projects ship an initial migration generated by the CLI.
